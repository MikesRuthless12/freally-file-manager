Freally File Manager 1.0.0 — Latest release

The complete byte-exact copy engine, desktop app, and CLI — verify-after-copy, pause/resume, two-way sync, secure delete, and cloud backends, all in one release.

New in 1.0.0

1.0 is a correctness release. Every feature from 0.22 is here; what changed is a full review of the codebase, section by section, and the fixes that came out of it. Several were quiet enough to lose data without ever showing an error, so this is worth taking.

  • Fixed: copying a folder that is itself a shortcut (a symlink or junction) copied nothing at all, and reported success. On the sync side the same flaw could empty the other side instead. Freally now refuses such a folder and says why, rather than appearing to work.
  • Fixed: cancelling a large folder copy could hang instead of stopping. The copy is now cancellable at any point.
  • Fixed: files uploaded to Freally’s S3 server by the AWS CLI or an AWS SDK were stored damaged — the transfer’s own framing was written into the file. Those uploads now arrive byte-for-byte, and a truncated one is rejected instead of stored.
  • Fixed: a sync pair whose database sat inside one of its own folders treated that database as a file to sync, and could delete it mid-run.
  • Fixed: SFTP remotes never worked. Every SFTP connection test and transfer failed with a configuration error no matter how it was set up.
  • Fixed: encryption could fall back to writing plaintext if the key could not be prepared. It now stops the job instead.
  • Fixed: read-only server mode was not fully read-only — one request type could still write.
  • Fixed: a resumed scan reported the wrong file total afterwards, so progress bars were wrong in both directions.
  • Fixed: signing in to a cloud provider could fail for no visible reason, because the browser opened a speculative connection first. Abandoning a sign-in also leaked a thread each time.
  • Fixed: a server pinned to a known_hosts file was refused whenever it offered a key type other than the first one listed — which is most of the time on a normally-configured machine.
  • Fixed: ntfy phone notifications arrived as raw code instead of the message.
  • Fixed: Escape closed the wrong dialog when two were stacked, and a few panels of Settings were laid out incorrectly.
  • Fixed (security): on Linux and macOS, another program running as you could hijack the administrator prompt. It swapped in its own connection while the password dialog was up, so the moment you approved, it — not Freally — was the thing running as administrator, free to read or write any file on the machine. The prompt no longer works in a way that can be swapped like that.
  • Fixed: uploading a file larger than about 8 MB to Freally’s S3 server failed outright. The AWS command-line tool and the AWS libraries split big uploads into parts without being asked, and Freally had no way to accept them. It does now, and it checks that every part is one you actually sent.
  • Fixed: phone notifications could never arrive. Four separate things were wrong on the way out — for Android the message did not say which phone to deliver to, and for iPhone it was missing the header Apple requires. Both are now sent correctly. You will need to fill in the iOS app identifier under Settings → Mobile for Apple pushes.
  • Fixed: on Windows and macOS, two names differing only in capitalisation — Photo.jpg and photo.jpg — are one file, but sync treated them as two. It copied each over the other, and a mirror could then delete the survivor. They are one file again.
  • Serving a folder that lives on a network drive no longer lets one slow response hold up every other request.
  • Documentation that promised behaviour the code did not have has been corrected rather than left standing.

What's included

  • Byte-exact copy engine with verify-after-copy (xxHash3, BLAKE3, SHA-256), pause/resume/cancel, and collision policies (Keep both, Skip, Overwrite, Overwrite if newer, Ask).
  • Secure multi-pass file shredding: Zero, Random (CSPRNG), DoD 3-pass, DoD 7-pass, Schneier 7-pass, VSITR 7-pass, Gutmann 35-pass, NIST 800-88 Clear — with SSD advisory.
  • Platform fast-paths: reflink/clonefile, CopyFileExW, copy_file_range(2), sendfile — auto-selected per filesystem.
  • Shell integration on every platform: Windows IExplorerCommand, macOS Finder Sync + Services, Nautilus, Dolphin ServiceMenu, Thunar Custom Actions.
  • Global paste hotkey (Ctrl+Shift+V / Cmd+Shift+V), clipboard watcher, history & totals, profiles, and 18-language UI.
  • 12 cloud backends via OpenDAL + SFTP: S3, GCS, Azure Blob, Backblaze B2, Cloudflare R2, DigitalOcean Spaces, Wasabi, MinIO, WebDAV, FTP, and more.
  • 2 429 MiB/s throughput on a modern NVMe — +86 % faster than Robocopy on the same hardware.

Roadmap

  1. Shipped
    Per-OS installers & signed auto-updater

    MSI / NSIS (Windows), DMG (macOS — Intel + Apple Silicon), deb / rpm / AppImage (Linux), plus a free ed25519-signed auto-updater. Shipped in 0.20.0.

    Shipped · 0.20.0
  2. Shipped
    Server mode & observability

    Run Freally File Manager headless as a WebDAV / HTTP / S3 / SFTP file server over any folder — read-only mode, bearer or HTTP-Basic auth, AWS SigV4 on the S3 API, a Prometheus /metrics endpoint, OpenTelemetry trace export, and Slack / Discord / ntfy.sh / Pushover webhooks. Launch it with the freally serve command, or set it up in the new Settings → Server panel.

    Shipped · 0.20.0
  3. Shipped
    Mount-as-filesystem, enterprise audit log, encryption & compression

    Mount any cloud backend or snapshot as a local drive (FUSE / WinFsp), export a tamper-evident WORM audit log in Syslog / CEF / LEEF / CSV / JSON formats, and encrypt (age) or compress (zstd) on the fly.

    Shipped · 0.20.0
  4. Shipped
    Sandboxed post-copy plugins

    Run third-party WebAssembly plugins after a copy, move, or job — fuel- and memory-capped, wall-clock-bounded, and gated by explicit per-plugin capabilities. Install from a file or hash-pinned URL in Settings → Plugins, with sample plugins for EXIF-based organizing and Discord / ntfy notifications.

    Shipped · 0.20.0
  5. Shipped
    Named queues & drag-merge

    Group transfers into named queues per drive, drag one queue's tab onto another to merge their progress into a single operation, press F2 to auto-enqueue the next job, and pin tray destinations for one-drop copies.

    Shipped · 0.20.0
  6. Shipped
    Live copy diagnostics

    When a transfer slows down, a header badge names the bottleneck — source disk, destination disk, network, antivirus, CPU, or thermal throttling — with a live throughput sparkline, backed by a real per-OS disk-busy sampler.

    Shipped · 0.20.0
  7. Next
    Signed builds

    Azure Trusted Signing on Windows and Apple notarization on macOS — no more SmartScreen or Gatekeeper prompts.

    Planned
  8. Beyond
    Three-way merge & richer plugin APIs

    Interactive three-way merge for sync conflicts, plus expanded WASI host APIs so plugins can read and write files directly under their granted capabilities.
